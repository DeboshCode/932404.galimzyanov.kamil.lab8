# Трекер чтения книг

Лабораторная работа №8, вариант 16. Камиль Галимзянов, группа 932404.

Приложение ведёт дневник чтения: добавление, просмотр, редактирование и удаление записей, отчёт за неделю или месяц, календарь чтения, суммарные страницы и прогресс по каждой книге.

## Запуск

Нужен Node.js 22 или новее с npm. В каталоге проекта выполните:

```sh
npm ci
npm start
```

Откройте http://localhost:3000. Сервер работает на локальном интерфейсе. Остановка: Ctrl+C.

При первом запуске создаётся `data/reading.sqlite`; в архиве уже находится пустая база с таблицами. Записи сохраняются после остановки и повторного запуска. Другой порт можно задать переменной `PORT`, другой файл базы — `DATABASE_PATH`:

```sh
PORT=3001 DATABASE_PATH=./data/reading-test.sqlite npm start
```

## Работа с дневником

- Кнопка «Добавить запись» открывает форму с названием книги, числом прочитанных страниц, датой и необязательной заметкой. В запись вводится количество страниц, прочитанных за этот сеанс, а не номер последней страницы.
- Переключатели «Неделя» и «Месяц», дата и стрелки меняют период. Неделя начинается в понедельник и заканчивается в воскресенье, месяц включает все календарные дни. Границы включены в выборку.
- Четыре показателя относятся ко всему выбранному периоду: страницы, дни с чтением, книги и записи. Книги с одинаковым названием после удаления пробелов по краям считаются одной книгой; регистр учитывается.
- Календарь показывает месяц выбранной даты и соседние дни до полных шести недель. Число под датой — сумма страниц за день. Выбор дня оставляет в списке его записи; «Весь период» снимает этот фильтр. Если день вне периода, период переключается на него.
- В блоке прогресса отображаются книги, по которым есть записи в выбранном периоде. Объём книги можно указать в форме записи или отдельно в карточке. Прогресс равен страницам по этой книге за всё время, делённым на её объём. Полоса ограничена 100%, при этом фактическая сумма не обрезается. Без объёма показывается сумма страниц и предложение его задать.
- Редактирование открывается в модальном окне. Перед удалением требуется подтверждение. Формы закрываются кнопками или Escape; незаписанные изменения отменяются.

## Стек и структура

HTML5, CSS3 (Flexbox и Grid), JavaScript ES modules, fetch и async/await, Node.js, Express, SQLite через better-sqlite3. Внешние сервисы и ключи не нужны.

## Схема базы данных

```text
reading_logs
  id          INTEGER PRIMARY KEY AUTOINCREMENT
  book_title  TEXT NOT NULL
  pages_read  INTEGER NOT NULL, > 0
  date        TEXT NOT NULL, YYYY-MM-DD
  notes       TEXT NOT NULL, по умолчанию пустая строка

book_goals
  book_title  TEXT PRIMARY KEY
  total_pages INTEGER NOT NULL, > 0
```

`reading_logs` содержит записи из задания. Дополнительная таблица `book_goals` хранит объём книги для полосы прогресса. Он общий для всех записей с этим названием и не сбрасывается при смене периода. Удаление последней записи не удаляет сохранённый объём; при повторном добавлении книги он используется снова.

Индексы ускоряют выборку по дате и группировку по книге. Все значения передаются в SQL через параметры. Запись и переданный вместе с ней объём книги сохраняются в одной транзакции. Сводка, книги и календарь читаются в одной транзакции. Даты рассчитываются без сдвигов часового пояса: календарные вычисления выполняются в UTC, текущая дата определяется по локальному времени сервера.

Сервер применяет `schema.sql` автоматически. При наличии утилиты sqlite3 можно создать базу вручную из корня проекта:

```sh
mkdir -p data
sqlite3 data/reading.sqlite < schema.sql
```

## API

Базовый адрес: `http://localhost:3000`. Тела POST и PUT передаются как JSON с заголовком `Content-Type: application/json`. Ответы API не кэшируются.

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/reading-logs?period=week&date=2026-11-15` | 200, записи и сводка за неделю |
| GET | `/api/reading-logs?period=month&date=2026-11-15` | 200, записи и сводка за месяц |
| GET | `/api/reading-logs/:id` | 200, одна запись |
| POST | `/api/reading-logs` | 201, созданная запись; `Location` содержит её URL |
| PUT | `/api/reading-logs/:id` | 200, обновлённая запись |
| DELETE | `/api/reading-logs/:id` | 204, без тела |
| PUT | `/api/book-goals` | 200, сохранённый объём книги |
| DELETE | `/api/book-goals?book_title=Название` | 204, объём книги сброшен |

Без параметров GET выбирает текущий месяц. `period` принимает только `week` или `month`; `date` — существующую дату в формате `YYYY-MM-DD`. Повторяющиеся параметры отклоняются. Записи сортируются по дате от новых к старым, при одинаковой дате — по убыванию ID.

Ответ списка содержит:

```json
{
  "period": {
    "type": "month",
    "anchor": "2026-11-15",
    "start": "2026-11-01",
    "end": "2026-11-30",
    "month_start": "2026-11-01",
    "calendar_start": "2026-10-26",
    "calendar_end": "2026-12-06"
  },
  "entries": [],
  "stats": { "total_pages": 0, "entries_count": 0, "reading_days": 0, "books_count": 0 },
  "books": [],
  "calendar": []
}
```

Каждый элемент `entries` имеет поля `id`, `book_title`, `pages_read`, `date`, `notes`. `books` содержит `book_title`, `period_pages`, `total_read`, `total_pages` (null, если объём не задан). `calendar` содержит только дни с записями: `date`, `pages_read`, `entries_count`; остальные дни интерфейс достраивает как пустые.

Поля POST и PUT записи:

| Поле | Проверка |
| --- | --- |
| `book_title` | Непустая строка после trim, до 200 символов |
| `pages_read` | Положительное безопасное целое число JSON Number |
| `date` | Существующая календарная дата `YYYY-MM-DD` |
| `notes` | Необязательная строка до 5000 символов, по умолчанию `""` |
| `total_pages` | Необязательное положительное безопасное целое число; задаёт объём книги |

PUT заменяет данные записи полностью: название, страницы и дата обязательны, пропущенная заметка становится пустой. ID записи не меняется. Если `total_pages` пропущен, сохранённый объём книги не изменяется. Отдельный PUT объёма принимает `{ "book_title": "Название", "total_pages": 300 }`; книга должна иметь хотя бы одну запись.

Примеры запросов:

```sh
curl -i -X POST http://localhost:3000/api/reading-logs \
  -H 'Content-Type: application/json' \
  -d '{"book_title":"Мастер и Маргарита","pages_read":35,"date":"2026-11-15","notes":"Первая глава","total_pages":480}'

curl 'http://localhost:3000/api/reading-logs?period=week&date=2026-11-15'

curl -X PUT http://localhost:3000/api/reading-logs/1 \
  -H 'Content-Type: application/json' \
  -d '{"book_title":"Мастер и Маргарита","pages_read":42,"date":"2026-11-15","notes":"Уточнено число страниц"}'

curl -X PUT http://localhost:3000/api/book-goals \
  -H 'Content-Type: application/json' \
  -d '{"book_title":"Мастер и Маргарита","total_pages":480}'

curl -i -X DELETE http://localhost:3000/api/reading-logs/1
```

Ошибки возвращаются в виде `{ "error": "Понятное сообщение" }`. Неверные данные или параметры — 400; некорректный либо отсутствующий ID и неизвестная книга — 404; тело запроса больше 128 КБ — 413; внутренняя ошибка — 500. Ошибки не создают и не меняют записи. Пользовательский текст выводится через `textContent`, без интерпретации HTML.
